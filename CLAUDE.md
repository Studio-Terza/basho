# basho

This is an offline walking-trip guide, a Dioxus app (iOS and desktop). It shows whatever one trip file says. The bundled trip, `data/trips/sample.toml`, is a small made-up trip. The same data also produces a one-page-per-day printed fallback.

## Layout

- `data/trips/*.toml`: trip files. `sample.toml` is the built-in trip, a small made-up one; any other file renders with no code change.
- `crates/guide`: loads a trip file with `Trip::load` or by parsing its text with `FromStr`. Trip text is `Content`: a list of typed parts, never a bare string. A leaf in the list is connecting words (`Words`), and any other part is a table: `{ plan = "13:15" }`, `{ fact = { at = "12:44", source = "train", evidence = ... } }`, `{ unknown = "15:03" }` (shown with `?`), `{ entry = "{塩竈|しおがま}" }`, `{ place = "{仙台|せんだい}" }`, `{ distance = "450 m" }`, `{ span = "5 min" }`, `{ price = "¥1,000" }`, `{ train = "Hayabusa 45" }`, or `{ quote = "..." }` for source text kept whole. `Content` derefs to the `RubyText` it shows. Display text is `RubyText`, written `{漢字|かな}`. It rejects any kanji without a kana reading at load time. Words holding a clock time or a distance fail while parsing. `KnownNames` fails the load on words holding the name of a known entry, and on an entry or place part that names nothing. The text is read in stretches on separate threads (each `[[days]]` and `[[routes]]` table, the `[kana]` table and each `[[catches]]` table starts one), and read whole, with the whole file's error, when any stretch fails.
- `crates/report`: bug reports. A `Report` holds what was captured, as text, and an optional note. `ReportBook` is the list and `ReportStore` the files: one TOML file per report in `Library/Application Support/basho/reports`, which is kept out of the iPhone's backup. Export writes every report to `Documents/bug-reports.toml`; nothing else leaves that folder.
- `crates/wiki`: the offline trip wiki, built from a loaded trip with `Wiki::new`. Every day, goal, step, place, shop, restaurant, thing, inn, planned meal and evening is an `Entry` with an `EntryId`, found by `EntryKey`. An entry holds `Section`s of `Row`s; a section with no rows is left out, so nothing is invented. The entry parts of `Content` become links through `wiki.names().runs(..)`: a name two entries of one kind share links to neither. `Linked here` is built from those same parts. Shops and restaurants come from stops of kind `shop` and `food`, joined when the name and spot match; sights join the star point of that name. Planned meals are meal goals and food stops of 20 min or more, with the food stops of their stretch by type. An evening page lists what is within a 1.5 km walk of the inn, today or tomorrow. Days, goals and steps have no page of their own: following one opens Today there, and Today shows their `Linked here`.
- `crates/plain_text`: `PlainText`, text that holds no control character but newline, carriage return and tab. Any type that derives `Deserialize` and holds free text reads through it (`#[serde(try_from = "String")]`), because the `no_plaintext` lint rejects free text that enters from a file unchecked.
- `crates/map_class`: the map's vocabulary: `Zoom` and the road, surface, land, place and POI classes the tiles carry.
- `crates/tiles`: the tile archive, `basho.tiles`. `TileArchive` reads one tile by `TileId` without loading the file; `WrittenArchive` writes it.
- `crates/map_plan`: what our own layer draws. `MapPlan` builds the route, the marks and the walker as GeoJSON, and the frame for a `MapLevel` (leg, goal, day). `MapSent` sends only what changed, so a position fix sends the walker and nothing else. `KeyEntry` names what the key can show. Nothing but route, steps, markers and walker goes through it; everything else is the base map.
- `crates/app`: the Dioxus app, package `basho`, bundle ID `com.cinglein.basho` (`Dioxus.toml`).
  - Views are structs that implement dioxus's `IntoDynNode`, written `{SomeView::new(..)}` in `rsx!`, not `#[component]` functions, because free functions are banned. Only `App::render` and `TripScope::render` call hooks.
  - dioxus gets `mobile` on iOS and `desktop` on macOS; on Linux CI it compiles without a renderer.
  - Run it with `dx serve --platform ios` (simulator; needs Xcode) or `dx serve --platform desktop`, from `crates/app`.
  - A two-finger long press anywhere, or Report a bug in the day menu, saves a report and opens the Bug reports page (`Screen::Reports`). The page lists reports, takes a note on each, and exports them. The tracker's last five minutes of decisions (`DecisionLog`) go in the report.
  - `history::History` is the one back and forward list. Every link, tab and menu jump leaves a `Mark` (screen, visit, scroll top); a turn restores it exactly. A swipe right or left on a wiki page turns it, wiki pages keep a sticky bar with the back button, Index and section buttons, and Today and Map show a back chip naming the wiki page you came from.
  - `TripInput` picks the trip at launch: a path given as the first argument, else the chosen trip in `Library/Application Support/basho/chosen-trip.toml`, else `Documents/trip.toml` on the phone, else the built-in `data/trips/sample.toml`. A named file that can't be read fails; it never falls back.
  - The map is MapLibre GL JS in the WebView (`assets/maplibre-gl.js`, `assets/maplibre-gl-worker.js`, v6.14.0, BSD-3-Clause). `assets/map_engine.js` runs in one `document::eval`, started by `MapFeed` from `App::trip_page`. It moves one map host into whatever `.map-slot` is on the page, so leaving the map tab keeps the map. Tiles come from `/tiles/z/x/y`, a Rust asset handler over the archive; MapLibre's worker never touches the network. There is no `glyphs` URL: all text is drawn from the phone's fonts. The style is `assets/map_style.json`, greyscale, with a layer's `metadata.key` naming its `KeyEntry`. Road width is importance, major roads are double lines, solid is paved, dashed is unpaved, dotted is trail.
  - Guide mode is framed: the engine fits the level's bounds, pinch changes the level, and swipe steps at that level (`Spot::stepped_across`). Explore frees pan and zoom, swipes leave the map alone, and the Guide button returns and refits. The key lists what the map draws on screen now, sent by the engine when it goes idle. Tapping a mark shows its kind and name under the top row. A feature with an English or romaji name shows it. A kanji name shows two lines, kana above kanji (one line, kana then kanji, on roads). The tile build takes the kana from OSM `name:ja-Hira`, `name:ja_kana` or `name:ja-Kana` (tile tag `reading`), else generates it with `jpreprocess` and its bundled NAIST-JDIC dictionary (tile tag `guess`), at build time only; the style marks a generated reading with a leading `≈`, so it needs no colour. The app carries only the tag text.
  - Light and frame: reading areas are always light, whatever the phone's setting. The frame (tab bar, day menu, wiki bar, status strip, map top bars) takes the `--frame-*` tokens in `main.css`, which are dark. Colour is written only in the token blocks, and every pair holds contrast in greyscale. Map land is a mid-light grey. The Trip page has a `Dark after sunset` switch, off by default and kept in `Library/Application Support/basho/dark-after-sunset.txt`. When on, `Appearance::chosen` turns the screen dark from `Day::sunset` (computed from the date and place, offline) until midnight, through the `.theme-dark` marker that `html:has(.theme-dark)` reads; the map canvas is inverted then.
  - Battery: `now` moves once a minute, so nothing re-renders on a clock tick. A fix under 10 m from the last one is dropped (`Sighting::kept_over`). GPS drops to 100 m accuracy while halted, the compass reports every 10° at most, and progress goes to disk on the minute, only when it changed. The system's own distance filter is not used: it would stop fixes while standing still, and the tracker would read that as a lost GPS.
  - The trip picker: the Trip button in the head of the left-edge menu opens a plain page (`Screen::Trip`). `TripShelf` holds the shown trip. A picked file replaces it only if it loads and is saved as the chosen trip; otherwise the page shows why and nothing changes. A new trip gets a fresh session, in a keyed list because dioxus ignores a key on a single child, and clears the old trip's place, trail and progress. If the chosen trip fails at launch, the failure page shows the same picker.
  - The file input is a real `<input type="file">`. Dioxus intercepts a click on one and asks Rust for the files, and on iOS that always returns none. So `TripShelf::LISTENER` stops the click before Dioxus sees it, WebKit shows the phone's own picker, and the listener reads the file and sends its text to Rust. The `phone_check` example runs that listener in Chrome.
- A trip file is one TOML file with these sections, in this order. Everything from `[[routes]]` on is generated.
  - `[trip]` holds the `name` and the `utc_offset`, such as `"+09:00"`. Every clock in the app reads this fixed offset.
  - `[[arcs]]` groups days into arcs. `[[places]]` holds place cards: name, meaning, geography, dated primary-source excerpts, disagreements between sources.
  - `[[days]]` is a day of **road-by-road legs**: each leg is one road, path or ride, and ends where the walker has to decide something. A leg has its `way`, `heading`, `handrail`, `km`, `minutes`, `start`/`end`, a `then` (the decision at its end), `see` and `too_far` facts, and `along` (stops), `branches`, `cards` and `notes`.
  - A leg's `mode` is `"walk"`, `"bus"`, `"boat"`, `"car"`, or a train: `mode = { train = { platform = ..., headsign = "...", line = "...", kind = "local", evidence = ... } }`. A bare `mode = "train"` fails at load, and so does a train missing any of the five. `platform` is `"not_published"` or `{ published = { number = 10, evidence = { source = { url = "...", checked = "..." } } } }`: a number can't be written without what backs it, and an unknown platform is never guessed. `headsign` is the board text, ending in `{行|ゆ}き`, or in `{方面|ほうめん}` when the sources give only a direction. `kind` is `local`, `rapid`, `limited_express`, `shinkansen` or `subway`.
  - A walking leg's mode is `mode = { walk = { reason = ... } }`, and a bare `mode = "walk"` fails at load. The reason is `"none_recorded"` or `{ recorded = { kind = "...", refers = { entry = "..." }, evidence = ... } }`. `kind` is `point_of_interest`, `avoids_road`, `shorter`, `basho_path` or `quieter`. `refers` is one `entry` or `place` part, checked like any other name. A reason is written only where the trip's own text for that leg, or a file in `research/`, states it. The app shows it in a `WHY THIS WAY` row after `WHY`, and the printed row shows `Why this way:`. A leg with no reason says `No reason recorded` in words. Other legs carry no reason.
  - A train's Get on step in the app opens with a `TRAIN` row: platform, headsign, line and kind, before `WHY`. Its printed row opens with the same facts.
  - Every fact that can be wrong carries `evidence`, and loading fails without it. It is one of `{ unverified = "why not" }`, `{ source = { url = "...", checked = "2026-10-01" } }` (a page or a file), `{ simulator = { url = "...", checked = "..." } }` (a record of a simulator run), or `{ owner = { url = "...", checked = "..." } }` (a record of the owner using it). The last three each name what backs them and when. It sits on every note and `see` fact, on `[days.night]`, on every train and on every `fact` time. A planning file (anything under `planning/`) cannot back a fact: a `source`, `simulator` or `owner` that cites one fails at load, because a plan can't verify itself. A fact stays unverified unless a file in `research/` or an outside page supports it.
  - Every time in a trip file is marked. `{ plan = "13:15" }` is a fixed target. `{ fact = "12:44", source = "train", evidence = ... }` is a timetable or hours fact, with one source word: `train`, `bus`, `boat`, `tour`, `booked`, `closes`, `entry`, `last_order`, `check_in` or `lands`. Write `source = "unknown"` when no source is known; it shows as "source unknown". A bare `"13:15"` fails at load.
  - A day also lists its `goals`: the handful of places the walker heads for, between a leg and the whole day. Each `[[goals]]` names the leg it ends on (`until`) and what it's `for`: `meal`, `sight`, `landmark`, `supplies`, or `{ star = [...] }`, which claims starred points by their `short` name. Rides and the walk to the night's inn are goals already: a run of rides ends one (named by the last ride's `to`), and so does any walk ending at the inn. A goal can instead be a loop of sights: `for = { loop = { sights = [{ leg = 12, name = [..], at = { plan = "13:49" } }, ..], stars = [..] } }`. It lists two or more sights in order, each naming the leg that reaches it and its planned arrival, which must equal that leg's end; `stars` claims starred points as a `star` goal does. The goal page shows the sights numbered with their times, and the goal-level map draws them as numbered stops (`loop_stop`). A sight name written as an `entry` part makes that name open the loop's goal page. Every leg belongs to exactly one goal, and a day has at most ten. Every starred point within 100 m of a walking line must be claimed by a goal on its day.
  - `[landmarks]` holds `peaks`, `ranges`, `seas`, `rivers` and `stars`, the points the trip is built around.
  - `[[routes]]` holds, for each `day`, the OpenStreetMap `ways` its walks use, and one line per leg, keyed by leg number. A ride's line is `{ coords = [...] }`. A walk's line is `{ segments = [...] }`, and nothing else loads:
    - `{ mapped = { nodes = [...], from = [lon, lat], to = [lon, lat] } }` follows OSM node ids. Every neighbouring pair must be an edge of a way in the day's `ways`, and the drawn points come from those nodes. `from` and `to` are optional: they start or end the segment part way along its first or last edge, within 1.5 m of it.
    - `{ no_mapped_path = { via = [...] } }` is a stretch on no known way. It reaches from the end of the segment before to the start of the segment after, through `via`. The map draws it as a broken line, with a hollow triangle at its middle on the current leg where it is long enough to hold one, and the step and the printed row warn in words.
    - Two mapped segments side by side must share their end.
    - A way is `{ id = 110277574, nodes = [[node, lon, lat], ...] }`, the used stretch of the OSM way, with no changes. Never add or edit a way by hand to make a line pass. If no way joins two places, the line says `no_mapped_path`.
  - After `[[routes]]`, `[kana]` and `[[catches]]` hold the catching features, written by `cargo xtask catch-import`, which cuts each note into parts with `KnownNames::drafted`. A trip file holds no map data: the base map is the tile archive.
  - Loading fails on bad TOML, an unknown key anywhere in the file, a number that is not finite, or missing furigana. `TripSource::findings` lists every other problem: text over its length limit (what keeps a leg on one screen), a walking line with a hop no way makes, a node on no way, a segment end off its way, two segments that do not meet, a walk with bare `coords`, times that don't add up, a walking pace outside 1.5–5.5 km/h, `km` that doesn't match the line, gaps between legs, stops far off the line, days out of order, a section that names a day twice or a day that isn't there, a route keyed to a leg the day lacks, a repeated place or arc, two starred points sharing a short name on one day, a date gap between days, and a place that isn't in `[[places]]`.
  - `cargo xtask trip-check [file]` prints those problems for `data/trips/sample.toml` or another trip file.
  - `crates/guide`'s `evidence` holds `Evidence`, `EvidenceKind` and `Backing` (evidence that must not be unverified), and `TripSource::evidence_counts` counts every `evidence` entry in a file by kind. The artifact of a passed `cargo xtask gate` lists those counts under `[evidence]`.
  - An unverified fact shows `?` where it is read: after a fact, after a fact time ("12:44 train ?"), in a train's board row, and after an inn's name. The printed pages do the same. The mark is a glyph, so it needs no colour.
- `crates/guide` also holds `geo` (distance, bearing, route snapping, the printed pages' `MapFrame` projection), `clock` (trip wall clock on `chrono`: dates, times and the trip's fixed UTC offset), `times` (`ClockTime` cannot print itself, so a shown time is one of: `FactTime` "12:44 train", `PlanTime` "plan 13:15" drawn lighter, or `LiveTime` "≈ 15:10 · 34 min of plan left", which needs a `Basis`, and the app draws them with `TimeView`), `leg`, and `guidance`: the current leg and how far along it, from GPS when a fix is within 150 m of a walking leg, otherwise estimated from when the leg was started and never past its end; off-route distance; and the pointers for lost mode.
- `vendor/dioxus-desktop`: dioxus-desktop 0.7.10, patched so the app comes back after iOS takes things away from a suspended app.
  - When the page process is terminated, or a page stops working, the window gets a fresh virtual dom (built from the same root and contexts) and loads the page again. The old application is dropped whole. Rendering waits until the new page reports in.
  - Every time the window becomes active, and after every reload, the page is asked over IPC whether it is the latest load, its edit socket is open on the current port and the app is mounted; edits left unacknowledged also count as broken. A page that fails is loaded again, at most three times until the next return.
  - When iOS throws away the app's scene in the background and brings it back, a new window with a fresh app is made.
  - The app keeps its screen, zoom and confirmed progress across a fresh virtual dom (`session::Place`), and shows the current leg again. Confirmed progress is also written to `Library/Application Support/basho/progress.txt` and restored on launch when it is for today.
  - Each step is written to `Documents/trail.log`, which the Files app shows under On My iPhone → Basho Walk.
- `xtask`: repository tooling.
  - `cargo xtask fuzz-trip [cases [seed]]` is the long fuzz campaign on the trip loader (default 5000 cases, seed 1). It runs the `fuzz_trip` tests in `xtask/tests/api`: arbitrary text, arbitrary bytes in a file, and the sample trip spoiled by line edits and awkward values. Every accepted trip must also build its wiki and its printed pages. `cargo test` runs the same tests for 32 cases with seed 0. A crash becomes a named regression test through the public API, then gets fixed.
  - `cargo xtask print` writes `target/print/basho-days.html`: one page per day, for printing as the fallback if the phone dies.
  - `cargo xtask ci` is the local gate: fmt, clippy, tests with the test-time budget, the shared lints, Basho's own lints, `trip-check` on every file in `data/trips`, then the `browser` step (the UI checks in Chrome, below). `--affected` limits clippy and tests to crates changed since `origin/main`.
  - `cargo xtask sim` proves the app on iOS. It makes a release build for the simulator, creates a fresh iPhone 16 Plus simulator (430 × 932), and runs the XCUITest project in `platform`, which drives real taps and drags (`TouchRecord` plays two-finger touches). The lint allows Swift only under a directory named `platform`, as test code, and the project is copied to `target/sim/uitest` to build. `tools/sim_ports` runs the tools and `tools/sim_suite` reads what they print. The procedure then checks crash reports by time and writes `target/procedures/<commit>/sim.toml`: each feature passed, failed or cannot be simulated, and the map's CPU and Mac energy figures by phase. Screenshots and the `xcodebuild` log sit beside it. Every `simctl` and `xcodebuild` call has a time limit. `xcrun simctl` is a script that runs `xcodebuild -runFirstLaunch` when CoreSimulator is older than Xcode expects, and that waits for an admin; a hang there means first launch has not been done.
  - `cargo xtask tile-build <file.osm.pbf> ...` rewrites `crates/app/assets/basho.tiles` with `osmium` from OpenStreetMap extracts: every zoom 7 to 14 within one 3.9 km cell of a walking leg, and zooms 7 to 11 along a ride. `tools/osm_items` reads an OSM feature into a `TileItem`, `tools/tile_shapes` holds the corridor and the geometry, and `tools/tile_draft` writes Mapbox vector tiles. The archive is committed: rebuild it only when the data or the tile schema changes, because each rebuild adds about 30 MB to history.
  - Goldens: `crates/app/tests/api/page_checks/golden/pages.sha1` holds a hash of every page of the built-in trip, with numbers cut to three decimals so it doesn't depend on the platform's maths. The print output has one too, in `tools/day_print`. They are recorded for the sample trip. After an intended change to the pages, run the test with `GOLDEN_BLESS=1`.
  - The UI checks (`crates/app/tests/api/ui_check`, `page_checks` and the `phone_check` example) render every screen for every day, place and card (about 1,000 stages). A unit test renders every stage in Rust and fails on a missing required element, a required element with no text or content, unrendered `{漢字|かな}` markup, `undefined`/`NaN`/`null`, an empty reading, a button with no label, and a plain class rule in the CSS (one with no pseudo-class or attribute part) that hides a class a required element uses. The browser tier (`cargo xtask browser`, and the `browser` step of `cargo xtask ci`) loads every stage in headless Chrome at iPhone 16 Plus size (430 × 932), the only phone the app targets. There is no sample: every stage loads. The tier is the example `crates/app/examples/phone_check`, so the tests and their 4 s and 1 s budgets do not include it, and tests need no Chrome. It has its own wall-time budget of 10 s, `[budgets.browser]` in `tooling/browser-budget.toml` (meta-xtask's policy has no browser measure, so Basho reads this file itself), with a warning line at 60%, 6 s (`[budgets.browser-warning]`). Over the budget, the step fails. Past the warning line, it prints a warning. The local gate status shows its time after the meta-dev steps. Chrome fails on page scroll, overflow, clipped or overlapping text (map labels included), content under the tab bar, a required element not shown, a fact or plan time that wraps, and furigana under 10 px. The tier then opens one page with the real engine, style and tiles from a local server, on software WebGL, and fails unless it draws major roads, streets, water and a goal, and asks for nothing off that server. That map page keeps the 430 × 932 screen at device scale 1, because the check reads which layers drew, not pixels. A tab that does not take the 430 × 932 screen fails. The example first proves its checks catch a broken page, then loads every stage; it exits non-zero on any problem. If a page does not load, it loads again in a new tab, at most two more times. A check that fails never runs again. The tier needs Chrome or Chromium: set `CHROME` to the binary, or have `chromium` on the PATH. When `CHROME` is set, the browser step starts one shared Chrome before its timer starts and passes it in `BASHO_CHROME_ENDPOINT`, so Chrome's launch is outside the 10 s budget. The gate sets it from the Playwright cache, and the GitHub Actions workflow sets `CHROME=chromium`, so the budget means the same thing on the laptop and the runner. Without `CHROME`, the example starts its own `chromium` from the PATH. The step prints the core count, the Chrome binary and each Chrome launch, and the time and Chrome CPU of the map check, the stages, the trip-file check and the broken page. Failing pages are saved to `target/ui-check/`.
  - The `style-kinds` lint (`cargo xtask style-kinds`, part of `cargo xtask lint`) stops any style from singling out one instance of a kind of screen. In `main.css` it refuses ids, attribute selectors with a value (except `role` and `lang`), `:nth-*`, `:first-child`, `:last-child`, `:only-child`, the `-of-type` forms, and any other pseudo-class that is not a shared state such as `:hover`, `:focus`, `:checked` or `:disabled`. It also refuses the `+` and `~` sibling combinators, and it looks inside `:has()`, `:not()`, `:is()` and `:where()`. Its parser skips comments and quoted strings. It reads rules inside `@media`, `@supports`, `@layer`, `@container` and `@starting-style`, and refuses any other at-rule and any nested rule. Attribute selectors are allowed only on `role`, `lang` and `open`, and only `role` and `lang` may be given a value. In the Rust markup, only `id`, `href`, `title`, `alt`, `key`, `aria-*` and `on*` handlers may carry instance data. A `class:` value must be a string literal or `.class()`, with no `if` or `match`, and every filled-in `{…}` must be a `.class()` call. `style:` must be a static string or a local typed `PoseStyle` or `PageShift`. Every other attribute must be a static literal or a closed enum's `.class()` or `.flag()`. `.class()` comes from the `Classed` trait over a workspace enum that derives `strum::IntoStaticStr` with a literal per variant, a hand-written conversion to `&'static str` fails, and `.flag()` is `match self` with a literal per arm. That covers `hidden`, `disabled`, `open`, `role`, `lang`, `data-*` and SVG attributes. SVG geometry may vary only in the mark shapes (`crates/map_plan/src/map_mark/`) and in the GPS arrow drawing (`screen/map_view/arrow_drawing.rs`). A `PoseStyle` can only come from `Menu::style`, which takes the menu's state, a `Pull` made from two touch points, and the viewport. A `PageShift` comes from a `Toward` and the viewport. So instances of a kind differ only in text, ids and `aria-*` values, which no selector can reach.
  - The map checks run in Rust in `crates/map_plan`: every walking leg draws as the current line, the frame holds a walker off the route, wider levels frame more of the day, and a position fix sends only the walker.
  - The shared lints are the `lint` binary from github.com/Studio-Terza/meta-dev, commit 10eaa0622553db3e7c53c0e1219b4a1f705fcecb, installed with `cargo install --git https://github.com/Studio-Terza/meta-dev --rev 10eaa0622553db3e7c53c0e1219b4a1f705fcecb --locked lint`, with no configuration, switches, baseline or allow-lists. `newtype` and `laws` come from tag v0.1.5, the latest tag; no tag yet covers that commit. Clippy, tests, affected selection, the test-time budget and mutation still come from `meta-xtask` (github.com/Cinglein/meta-dev); its lints no longer run.
  - `tooling/policy.toml` holds the test-time budget and the mutation limits for `meta-xtask`, whose parser still demands its old lint keys; they are unread. The browser budget is in `tooling/browser-budget.toml`.
  - `cargo xtask lint` runs the shared lints, then Basho's own (`tools/basho_lints`, `tools/style_lints`): `ownership`, `ui-numbers`, `style-lengths`, `style-motion`, `style-kinds`.
  - Mutation testing runs in GitHub Actions: a pull request job runs `cargo xtask mutants` (cargo-mutants on the lines changed against main) and fails when any mutant is missed, and a weekly sharded run of `cargo xtask mutants --full` reports the survivors. Locally either one prints the missed mutants per crate and writes `target/procedures/<commit>/mutants.txt`. It needs `cargo-mutants` installed. `.cargo/mutants.toml` is its config. `mutants-plan` stays the shared plan.
  - Basho's lints return a `Report` of `Violation`s at a `Site`. TestFlight lives in `tools/testflight_ports`; the text it parses (`Bearer`, `Fingerprint`, `XcodeVersion`) lives in `tools/apple_text`. Every xtask error is a `Failure` variant.

## Repository rules

- **CI must pass.** `cargo xtask gate` is the full check, and the GitHub Actions workflow runs it.
- **Everything is Rust.** Don't use Python, shell or other languages for tooling. Add tasks to `xtask` instead.

## Rust rules

The lints enforce all of these.

**Files and modules**
- **A type with several parts becomes a module directory:** `dir/mod.rs`, never `dir.rs` beside `dir/`.
- **Never name a type or module after a keyword.**
- **Modules nest by use** (`module-nesting`):
  - A file whose only outside users sit in one sibling module belongs inside that sibling.
  - A `use` path never reaches past a directory's `mod.rs` into its children.
  - A module directory re-exports at most 8 names.

**Code**
- **Zero comments,** including doc comments (`no-comments`). Use clear names and small functions instead.
- **No free functions** except `main` and `#[test]` functions (`no-free-fns`).
- **Lifetimes are named with a word,** never a single letter (`named-lifetimes`).
- **Function names say what the function does** (`literal-names`).
  - No names under three letters.
  - No vague names: `get`, `set`, `make`, `check`, `build`, `handle`, `process`, `data`, `value` and the like.
  - `new` is allowed.
- **At most 4 private functions per type** (`private-fns`).
- **Function bodies stay flat** (`fn-shape`):
  - No local variable bound to a boolean.
  - No tuple literal bound to a local.
  - At most 4 parameters after the receiver.
  - Control flow nests at most two deep.
- **Iterators are driven by combinators,** not by `let mut` iterators or collecting loops (`manual-iteration`).
- **Types carry their meaning** (`type-shape`):
  - No `bool` struct field.
  - No tuple type in a signature or struct field.
  - No `Result<_, String>`. Errors are `thiserror` enums.
- **No two non-`pub` functions on one type share a signature** (`distinct-signatures`).
- **Casts:**
  - `as` casts only in const context.
  - Const loops walk slices, with no counter loops.
  - Use `From`, `TryFrom` or `EnumMap` elsewhere (`const-shape`).
- **Derive enum plumbing with `strum`.** Index tables by enum with `enum_map::EnumMap`.

**State and invariants**
- **State is a transition graph** (`state-graph`):
  - A vertex is a type with `impl State for T {}`. An edge is a `pub` method that takes `self` by value and returns a vertex.
  - Every struct field is private.
- **Invariants live as high as possible:** a type first, then a const assertion, then a test.

**Conventions the shared lints read**
- **Processes start only in a crate ending in `ports` or a module named `ports`.** So do `remove_dir_all`, `mem::forget` and `env::temp_dir`, inside a `#[must_use]` guard.
- **Bit-level work sits in modules named `bits`.**
- **Tests go through public APIs in `tests/`.** Nothing in `src` is gated on `test`. A conversion pair or hand-written order has a law from meta-dev's `laws` crate.
- **The same public method on three types is `AsRef<T>` or `From<&T>`, derived where it can be; a trait needs generic code that uses it.** Newtype plumbing comes from meta-dev's `newtype` derives.

**Clippy**
- **Clippy pedantic must pass.** Never use a blanket `allow`.
- **Use `#[expect(clippy::name, reason = "...")]`** on the smallest item that needs it.

## Guide content rules

- **Verify every fact against a source.** Record its `evidence`: what backs it and the date it was checked, or why nothing does.
- **Mark perishable facts as perishable:** bus times, trail status, opening hours.
- **Only quote primary-source excerpts from texts actually fetched,** never from memory.
  - Show the original beside every translation, and label our own translations as ours.
  - Never bundle copyrighted modern translations.
- **Readers may read kana but not kanji.**
  - Every kanji gets furigana at a readable size.
  - Excerpt originals are exempt: they're a folded secondary layer, and classical texts have no sourced readings.
  - Place-name readings come from a source, not from a tokenizer.
- **No photos.**
